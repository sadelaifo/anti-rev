本系统采用「板卡(下位机)采集 → 离线服务器消费存储」的部署架构。板卡(位于 1/11 号槽)上运行 2 个 Kafka 发送端(发送端 A、发送端 B),负责将采集数据以消息形式发送至离线服务器;离线服务器上同机部署 Kafka、Python 消费服务与 Redis,由 Python 服务消费 Kafka 消息并写入 Redis 完成落地存储。

根据存储规模需要,Redis 提供基础模式与集群模式两种部署形态,二者仅在 Redis 的部署方式上不同,数据链路保持一致。

基础模式(非集群)
采用单台离线服务器部署,Kafka、Python 消费服务与 Redis 均运行在同一台服务器上,其中 Redis 为单实例(standalone),不组建集群。板卡发送端的数据经该节点 Kafka 进入,由 Python 消费服务写入本机 Redis 单实例。该模式部署简单,适用于数据量较小、无需高可用的场景,是系统的基础部署形态。

集群模式(可横向扩展)
在基础模式之上,将 Redis 由单实例扩展为集群,以满足更大规模的数据存储与高可用需求。此模式下 Kafka 与 Python 消费服务仍为单节点,不做扩展;仅 Redis 扩展为多节点集群。集群由 3 台离线服务器组成,每台部署 1 主 1 备(1 Master + 1 Replica),合计 3 主 3 备、共 6 个节点。数据按 slot 分片路由并写入各主节点,主节点通过主从复制将数据同步至对应备节点,当主节点故障时可由备节点接管,保证数据的可扩展性与可用性。集群规模可按需配置(如 3 节点或更多节点),当前采用 3 主 3 备的配置。
